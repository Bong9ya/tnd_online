# TND · 상품 수익과 재고 관리

상품 원가에 **배송비와 판매 수수료를 반영한 예상 이익**을 계산하고, **매입처별 상품·재고·입고·출고**를 관리하는 한국어 웹 도구입니다.

## 가장 쉬운 실행 방법

1. 이 저장소에서 **Code → Download ZIP**으로 파일을 받습니다.
2. 압축을 풀고 **`TND_Seller_Workspace.html`** 파일을 Chrome 또는 Edge에서 엽니다.
3. **상품 등록**을 누르고 상품명, 매입처(공급사), 원가, 판매가를 입력합니다.
4. 배송비·수수료·최초 재고를 입력하고 **상품 등록**으로 저장합니다.

단일 HTML 파일에는 화면과 프로그램이 모두 포함되어 있습니다. 설치나 회원가입 없이 사용할 수 있습니다.
`index.html`을 열어도 됩니다. 이 경우 `styles.css`, `core.js`, `app.js`를 같은 폴더에 두세요.
GitHub의 파일 보기 화면은 프로그램을 실행하는 화면이 아닙니다. 파일을 내려받아 열어주세요.

## 입력 항목

| 항목 | 입력 기준 |
| --- | --- |
| 상품명 / 상품 코드 | 상품명은 필수입니다. 코드는 선택이며, 같은 매입처 안에서는 중복 코드를 등록할 수 없습니다. 매입처가 다르면 같은 코드를 사용할 수 있습니다. |
| 매입처(공급사) | 직접 입력하거나 기존 이름을 선택합니다. 생략하면 ‘매입처 미지정’으로 분류됩니다. |
| 상품 원가 | 판매할 상품 **1개**의 원가 |
| 판매가 | 고객에게 받는 상품 가격 |
| 실제 택배비 | 판매자가 택배사에 지불하는 배송비 |
| 고객 배송비 | 고객에게 별도로 받는 배송비. 무료배송은 0원 |
| 포장비 | 판매 1건에 들어가는 포장 비용 |
| 판매 수수료율 | 판매 채널에서 적용하는 수수료율(%)을 직접 입력. 소수 둘째 자리까지 |
| 추가 고정 수수료 | 1건당 별도 부과되는 고정 비용. 없으면 0원 |
| 고객 배송비에도 수수료 적용 | 해당 채널에서 배송비에도 수수료를 부과할 때 선택 |
| 최초 재고 | 상품을 처음 등록할 때 보유한 수량 |
| 재고 알림 기준 | 현재 재고가 이 수량 이하가 되면 부족 표시. 0개는 품절 |

기본값 0%는 실제 판매 채널의 수수료율을 뜻하지 않습니다. 해당 판매 채널의 정산 기준을 확인해 입력하세요.

## 계산 방식

- 수수료 기준액 = 판매가 + (배송비에도 수수료 적용 시 고객 배송비)
- 예상 수수료 = **수수료 기준액 × 수수료율 ÷ 100을 원 단위 반올림** + 추가 고정 수수료
- 예상 이익 = **판매가 + 고객 배송비 − 상품 원가 − 실제 택배비 − 포장비 − 예상 수수료**
- 이익률 = 예상 이익 ÷ (판매가 + 고객 배송비) × 100
- 수입이 0원이면 이익률은 계산하지 않고 ‘—’로 표시합니다.

예: 원가 4,500원, 판매가 12,900원, 고객 배송비 3,000원, 택배비 3,200원, 포장비 300원,
수수료율 5.5%, 배송비에도 수수료 적용, 고정 수수료 0원이면 수수료 **875원**, 예상 이익 **7,025원**입니다.

**상품 1개를 1건 발송하는 기준**입니다. 합배송이나 여러 개 묶음 판매는 1개당 비용을 나누어 입력하세요.
부가세·광고비·반품비·채널별 세부 정산 규칙은 자동 계산하지 않습니다. 실제 정산 내역과 비교해 사용하세요.

## 재고 관리

- 상품을 등록하면 최초 재고가 입고 이력으로 남습니다. 0개로 시작하면 입고 이력은 추가하지 않습니다.
- 상품 목록의 **입출고**를 누르고, 입고 또는 출고·수량·메모를 입력합니다.
- 현재 재고보다 많은 수량은 출고할 수 없습니다. 음수·소수 재고도 저장하지 않습니다.
- **입출고 이력**에서 기록을 확인할 수 있습니다. 수량을 잘못 입력했다면 반대 방향의 입출고를 기록하고 메모를 남기세요.
- **재고 원가 총액**은 각 상품의 현재 원가 × 현재 재고의 합입니다. 원가를 수정하면 이 금액도 바뀝니다.
- 출고는 수량만 변경합니다. 판매 매출이나 실제 실현 이익을 누적하지 않습니다.
- 네이버·쿠팡 주문과 자동 연동하지 않습니다. 입출고는 직접 입력합니다.
- 원화는 0~10억 원의 정수, 상품별 재고는 0~100만 개, 상품은 최대 5,000개까지 입력할 수 있습니다.

## 매입처(공급사)별 관리

1. **상품 등록·수정 → 매입처(공급사)**에 이름을 입력합니다. 이전에 사용한 이름은 입력 목록에서 선택할 수 있습니다.
2. **매입처 관리**에서 매입처별 상품 수, 현재 재고, 재고 원가 총액, 재고 확인이 필요한 상품 수를 확인합니다.
3. 각 매입처의 **상품 보기**를 누르면 해당 공급사의 상품만 표시되고, 상단의 재고·원가 요약도 같은 매입처 기준으로 바뀝니다.
4. 상품 목록과 입출고 이력의 매입처 선택란으로 공급사를 전환합니다. **전체 매입처로 보기**로 돌아갈 수 있습니다.
5. 매입처 관리의 연필 버튼에서 이름을 바꾸면 해당 매입처 상품들의 이름이 함께 변경됩니다. 상품 ID·원가·재고·입출고 기록은 유지됩니다. 기존 매입처와 같은 이름으로 합치는 기능은 제공하지 않습니다.

- **같은 상품을 여러 공급사에서 매입한다면 공급사별로 상품 행을 나누어 등록**하세요. 매입처가 다르면 같은 상품 코드도 등록할 수 있으며, 원가와 재고는 각 상품 행에서 따로 관리합니다.
- 매입처는 상품에 입력한 이름을 기준으로 자동 집계됩니다. 상품 없이 공급사만 따로 등록하는 방식은 아닙니다.
- 이전 버전에서 저장한 상품이나 백업에 매입처가 없으면 **매입처 미지정**으로 불러옵니다. 상품 수정에서 하나씩 지정할 수 있습니다.
- 입출고 이력의 매입처 필터는 **상품의 현재 매입처**를 기준으로 합니다. 상품의 매입처를 바꾸면 기존 이력도 현재 매입처에서 조회됩니다. 입고 건마다 공급사를 나누는 매입 장부는 제공하지 않습니다.
- JSON 백업에는 매입처 정보가 포함됩니다. 새 파일을 다른 위치에서 열기 전에는 기존 버전에서 백업하고, 새 버전에서 복원하세요.

## 저장, 백업과 다른 기기에서 이어 쓰기

자료는 **현재 브라우저의 로컬 저장소**에 저장됩니다. GitHub에는 프로그램 코드가 저장되며, 입력한 상품과 재고가 자동 업로드되지는 않습니다.
파일을 옮기거나 브라우저·접속 주소를 바꾸면 저장 위치도 달라질 수 있습니다.

- **백업**: 전체 상품과 입출고 이력을 JSON 파일로 내려받습니다.
- **복원**: JSON 백업을 불러와 현재 자료를 교체합니다. 교체 전에 확인 창이 나옵니다.
- **CSV 내보내기**: 현재 선택한 매입처의 전체 상품(전체 매입처 선택 시 모든 상품)의 매입처·원가·비용·예상 이익·재고를 엑셀에서 열 수 있는 CSV로 내려받습니다. 검색어·재고 상태 필터는 CSV에 적용하지 않습니다. CSV에는 입출고 이력이 포함되지 않으며 복원용으로 사용할 수 없습니다.
- PC에서 노트북으로 옮길 때는 **PC에서 백업 → 파일 전달 → 노트북에서 같은 프로그램을 열고 복원**하세요.
- 브라우저 자료 삭제·시크릿 모드 종료에 대비해 주기적으로 백업하세요. 자동 동기화나 서버 백업은 제공하지 않습니다.
- 다른 창에서 자료가 변경되면 덮어쓰기를 막고 새로고침을 안내합니다.
- 저장에 실패하면 성공으로 표시하지 않습니다. 손상된 기존 자료도 자동으로 덮어쓰지 않습니다.
- ‘예시 데이터로 둘러보기’는 실제 상품과 무관한 예시 3개를 불러옵니다. 자료가 이미 있으면 교체 확인을 요청합니다.

## 개발 및 검증

외부 라이브러리를 사용하지 않습니다. Node.js 18 이상이 있으면 다음 명령으로 테스트와 로컬 미리보기를 실행할 수 있습니다.
의존성 설치는 필요 없습니다.

```sh
npm test
npm start
npm run build
```

- `npm start`: `http://127.0.0.1:4173`
- `npm run build`: 원본 파일에서 `TND_Seller_Workspace.html`을 다시 생성
- 수익 계산·배송비 수수료·반올림·잘못된 입력·입출고·재고 한도·백업 복원·매입처별 집계·매입처 이름 변경·매입처별 코드 중복·CSV 안전성 등 자동 검사 30개
- v1.1 매입처 기능의 초기 화면 표시는 확인했으며, 공급사 필터·이름 변경의 실제 화면 조작 검증은 완료하지 못했습니다.
- 브라우저에서 상품 등록/수정, 초과 출고 차단, 정상 출고, 새로고침 후 자료 유지, 입출고 이력, 검색과 필터, JSON 백업/복원 확인
- 1440px 데스크톱 및 390px 모바일 화면 확인

## 파일 구성

| 파일 | 역할 |
| --- | --- |
| `TND_Seller_Workspace.html` | 바로 열어 쓸 수 있는 단일 파일 버전 |
| `index.html` | 원본 화면 |
| `styles.css` | 데스크톱·모바일 화면 디자인 |
| `core.js` | 수익 계산과 재고·백업 검증 |
| `app.js` | 상품 관리, 입출고, 브라우저 저장, 백업과 복원 |
| `server.cjs` | 선택 사항인 로컬 미리보기 서버 |
| `scripts/build-standalone.cjs` | 단일 HTML 생성 도구 |
| `tests/core.test.cjs` | 핵심 계산 및 데이터 동작 테스트 |

단일 HTML은 생성된 파일입니다. 기능을 변경할 때는 원본을 수정하고 `npm run build`로 다시 만드세요.
